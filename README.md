# Dacha.kz — маркетплейс аренды загородных дач и коттеджей

MVP на Django: хосты публикуют объекты, гости ищут, бронируют и оплачивают.
Сфокусирован на загородном отдыхе (дачи, коттеджи, бани, глэмпинг, зоны отдыха).

## Возможности MVP

**Гость:** поиск/фильтрация по городу, типу, датам, гостям, удобствам · карточка
объекта с галереей и календарём занятости · бронирование с расчётом стоимости ·
оплата (демо) · «Мои брони» с отменой.

**Хост:** регистрация и режим хоста · создание/редактирование объектов с фото ·
управление календарём (блокировки дат) · приём и подтверждение заявок ·
мгновенное бронирование (instant) или подтверждение вручную (request-to-book).

## Стек

- **Backend:** Python 3.14 + Django 5.2 (серверный рендеринг шаблонов)
- **БД:** SQLite (MVP) → PostgreSQL (прод)
- **Frontend:** Django templates + ванильный CSS/JS (интерактивный календарь)

## Запуск

```powershell
py -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe manage.py migrate
venv\Scripts\python.exe manage.py seed          # демо-данные
venv\Scripts\python.exe manage.py runserver
```

Открыть http://127.0.0.1:8000/

## Защита от овербукинга

Два рубежа (см. `bookings/services.py`):

1. **`select_for_update()`** — блокирует строку объекта на время транзакции, чтобы
   параллельные брони одного коттеджа выполнялись строго по очереди (нет race condition).
2. **EXCLUSION-ограничение PostgreSQL** (`bookings/migrations/0002_*`) — на уровне БД
   запрещает вставку пересекающихся активных броней одного объекта. Активируется
   автоматически при переключении на PostgreSQL.

Логика интервалов — полуоткрытые `[check_in, check_out)`: день выезда свободен для
заезда следующего гостя (back-to-back брони разрешены).

## Переход на PostgreSQL (прод)

1. Раскомментировать блок PostgreSQL в `config/settings.py` → `DATABASES`.
2. `pip install "psycopg[binary]"`
3. `manage.py migrate` — миграция `0002` сама создаст `btree_gist` и EXCLUDE-ограничение.
